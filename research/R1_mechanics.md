# R1: ポケモンスリープ 個体評価の重み付け根拠（メカニクス調査）

- 調査日: 2026-09-11
- 対象ゲームバージョン: Ver.3.8.0（2026-09-09 実装）時点
- 目的: 個体評価アプリで使う「とくい別 × サブスキル/性格」の 0〜100 重みを、実測値と生産モデルから導出する

---

## 0. 先に結論（重要な発見だけ）

1. **英語圏ソース（Game8 英語版など）は古い。** Research EXP 6%、Energy Recovery 1.12、解放レベル 10/25/50/75/100 のままで、いずれも現行値ではない。日本語の wikiwiki と公式アップデート告知を一次情報とすべき。
2. **サブスキルのおてつだい時間短縮には「合計35%」の上限がある。** おてつだいボーナス5% + スピードS 7% + スピードM 14% はすべてこの枠を食い合う。性格補正はこの上限の外で別途乗算される。
3. **性格の「おてつだいスピード」は ±10% ではなく非対称。** ▲ はおてつだい時間 ×0.9（速度 1.11倍）、▼ は ×1.075（速度 0.93倍）。Ver.1.1.0 で ▼ のペナルティが緩和された結果である。
4. **げんき回復量▼▼ はモデル上ほとんど無害。** 睡眠スコア100 → げんき88 でも最速帯（81以上）の中に収まる。失うのは「最速帯にいられる時間が1日あたり約2時間短くなる」ぶんだけで、実質1〜2%の損失にすぎない。コミュニティの嫌われ方は Ver.1.1.0 以前（0.8倍）の記憶を引きずっている。
5. **最大所持数アップの価値は、きのみとくいでは低く、食材/スキルとくいで高い。** 所持数超過時、きのみはエナジーに自動変換されるが、食材は出現しなくなり、メインスキルの抽選も止まるためである（依頼文の想定とは逆になる）。
6. **チーム効果を満額で数えると、おてつだいボーナスは全とくいで最上位級**（5匹に5%）。自分だけの おてつだいスピードM（16.3%）の約1.6倍に相当する。

### 2-3. げんき回復量▲▼が実際にどう効くか

げんきの仕様（[wikiwiki/げんき](https://wikiwiki.jp/poke_sleep/%E3%81%92%E3%82%93%E3%81%8D)）:

- 消費: チーム編成中は **10分ごとに1**（＝6/時）減る。0未満にはならない
- 回復: 睡眠計測で **睡眠スコアの点数ぶん**回復。ただし睡眠だけでは **上限100**（げんき回復ボーナス保持者は105）。メインスキルやどうぐを使えば 150 まで乗せられる
- 速度補正（おてつだい時間にかかる倍率）:

| げんき | おてつだい時間の倍率 | 速度換算 |
|---|---|---|
| 150〜81 | **×0.45** | 2.222倍 |
| 80〜61 | ×0.52 | 1.923倍 |
| 60〜41 | ×0.58 | 1.724倍 |
| 40〜1 | ×0.66 | 1.515倍 |
| 0 | ×1.00 | 1.000倍 |

ここから、▲▼の実効を計算できる。

**▼▼（×0.88）の実損**

睡眠スコア100で起床すると、無補正は げんき100、▼▼は げんき88。どちらも**最速帯（81以上）の中**にいる。違いは最速帯から落ちるまでの時間だけ:

```
無補正: (100 − 81) ÷ 6 = 3.17 時間
▼▼    : ( 88 − 81) ÷ 6 = 1.17 時間
差     : 約 2.0 時間
```

この2時間は ×0.45 から ×0.52 の帯に移る（13.5%遅くなる）。起床後の活動16時間で均すと

```
損失率 ≒ 2.0h × 13.5% ÷ 16h ≒ 1.7%
```

つまり **自身の産出が約1.7%落ちるだけ**である。さらに、チームに げんき回復ボーナスが1つでもあれば 88 × 1.14 = 100.3 で完全に打ち消される（[wikiwiki/げんき回復ボーナス](https://wikiwiki.jp/poke_sleep/%E3%82%B5%E3%83%96%E3%82%B9%E3%82%AD%E3%83%AB/%E3%81%92%E3%82%93%E3%81%8D%E5%9B%9E%E5%BE%A9%E3%83%9C%E3%83%BC%E3%83%8A%E3%82%B9)）。

ただし短時間睡眠だと話が変わる。睡眠スコア70のプレイヤーなら 70 → 61.6 となり、**最速帯に一度も入れない**。この場合の損失は全時間帯に及び、5〜8%規模になる。[Aki久の検証](https://note.com/aki_hi_sa/n/nae7aa51d4209)も「睡眠スコア62までは無補正と同じ（誤差の範囲）」「げんき回復ボーナス2匹でスコア100時99%まで戻る」としており、結論は一致する。

**▲▲（×1.2）の実利**

睡眠スコア × 1.2 が 100 を超えると切り捨てられるため、**睡眠スコア84以上のプレイヤーには一切効かない**。8時間睡眠（スコア約94）なら完全に死にスキルである。スコア70程度の短時間睡眠者だけが 70 → 84 の恩恵を受ける（最速帯に約30分入れる程度）。

> **アプリ設計への示唆**: げんき回復量の ▲▼ は、ユーザーの平均睡眠時間を入力させて重みを動的に変えるのが本来正しい。固定値にするなら「ほぼ0」に寄せるべきで、少なくとも食材確率▼▼やスキル確率▼▼と同列に扱ってはいけない。

## 3. 生産モデル

### 3-1. 基本式

**おてつだい間隔**

```
表示おてつだい時間 = floor( 基準おてつだい時間 × レベル補正 × 性格補正 × サブスキル補正 × おやすみリボン補正 )
実おてつだい間隔   = 表示おてつだい時間 × げんき補正
1日のおてつだい回数 H = 86400 ÷ 実おてつだい間隔（帯ごとに積分）
```

- サブスキル補正 = 1 − min(0.35, おてつだいボーナス合計 + スピードS + スピードM)
- 性格補正 = 0.9（▲）／ 1.075（▼）／ 1.0
- 同カテゴリ内は加算、カテゴリ間は乗算（[wikiwiki/おてつだい](https://wikiwiki.jp/poke_sleep/%E3%81%8A%E3%81%A6%E3%81%A4%E3%81%A0%E3%81%84)）

**1回のおてつだいの中身**

```
食材おてつだい確率 p = 基礎確率 × 性格補正 × (1 + 食材確率アップの合計)
   → 確率 p で食材、確率 (1−p) できのみ
きのみ個数 B = 2（きのみとくい・オール） / 1（食材・スキルとくい）  ＋ きのみの数S があれば +1
メインスキル発生確率 q = 基礎確率 × 性格補正 × (1 + スキル確率アップの合計)
   → おてつだいのたびに独立に抽選
```

**産出**

```
きのみ産出 = H × (1 − p) × B
食材産出   = H × p × n食材
スキル発動 = H × q        （1日あたりの発生回数に上限あり／Ver.3.3.0で緩和）
```

### 3-2. 標準仮定

| 変数 | 値 | 根拠 |
|---|---|---|
| チーム人数 | 5匹（評価対象は総産出の 1/5 を担う） | ゲーム仕様 |
| げんき減少 | 6/時 | wikiwiki/げんき |
| 睡眠 | 8時間（睡眠スコア約94）、活動16時間 | 一般的な想定 |
| 食材おてつだい確率 基礎 | 平均 **20%**、種族により 10〜30%。きのみとくい≒15%、食材とくい≒25%、スキルとくい≒18% | [wikiwiki/おてつだい](https://wikiwiki.jp/poke_sleep/%E3%81%8A%E3%81%A6%E3%81%A4%E3%81%A0%E3%81%84)「平均すると20%程度」 |
| メインスキル発生確率 基礎 | きのみ/食材とくい 1.5〜3%、スキルとくい 3.5〜7% | コミュニティ早見表（**本調査で最も裏取りが弱い数値**。wikiwiki は種族別の数値を非公開としている） |
| 食材とくいの1回あたり食材個数 | 2個 | wikiwiki/とくい |

### 3-4. 所持数あふれ（最大所持数アップの価値）

**所持数超過時に何が起きるか**（[Game8/最大所持数](https://game8.jp/pokemonsleep/565251)）:

| | 挙動 |
|---|---|
| きのみ | **エナジーに自動変換される**（ロスは小さい） |
| 食材 | **出現しなくなり、すべてきのみに置き換わる**（完全なロス） |
| メインスキル | 「いつのまに育成」に移行後は **抽選そのものが行われなくなる**（完全なロス） |

したがって **最大所持数アップは、きのみとくいには効きが薄く、食材とくい・スキルとくいで効く**。依頼文にあった「slow/berry Pokémon で効く」という前提は逆になる。

**あふれ時間の式**

```
1時間あたり獲得個数 I = 3600 ÷ 実おてつだい間隔 × { (1 − p) × B + p × n食材 }
あふれまでの時間 t_full = 最大所持数 ÷ I
夜間ロス = max(0, 睡眠時間 − t_full)
その日の産出損失率 ≒ 夜間ロス ÷ 24h
```

**計算例（Lv.30 食材とくい、表示おてつだい時間 2400秒、げんき81以上帯）**

```
実間隔 = 2400 × 0.45 = 1080秒 = 18分 → 3.33回/時
I = 3.33 × (0.75 × 1 + 0.25 × 2) = 4.17 個/時
未進化（所持数21）  : t_full = 5.0 時間
＋最大所持数アップL : t_full = 39 ÷ 4.17 = 9.4 時間
```

睡眠8.5時間なら、Lなしは 3.5時間ぶんの食材を失い（夜の41%）、Lありはゼロになる。1日換算の食材損失は **約14%**。チーム寄与に直すと 14 ÷ 5 = **2.9 ポイント**。進化済み（所持数30前後）なら損失は5%程度、チーム寄与 1.1 ポイントまで下がる。

**きのみの数S との相互作用**: B が 2→3 になると I が1.5倍になり、t_full は 2/3 に縮む。きのみの数S と 最大所持数アップ は同じ個体で組ませると噛み合うが、食材とくいに きのみの数S を付けると「あふれを早めて食材を止める」方向に働くため、実質マイナスになりうる（[wikiwiki/きのみの数S](https://wikiwiki.jp/poke_sleep/%E3%82%B5%E3%83%96%E3%82%B9%E3%82%AD%E3%83%AB/%E3%81%8D%E3%81%AE%E3%81%BF%E3%81%AE%E6%95%B0S) も「あまり相性はよくない」と明記）。

[課金中毒者の日記の実測](https://www.fireyoshida.com/entry/2023/11/05/095826)でも、Lv30 の食材とくいで 最大所持数アップL があると あふれまで 3〜4時間延びる（カイロス 3h20m→6h30m、アブソル 3h→7h、フシギバナ 5h30m→9h）と報告されており、上式と整合する。

### 3-5. 評価指標: チーム寄与値（TV）

チーム効果を満額で数えるため、次の指標を使う。

> **TV = そのサブスキルによって「チーム全体のそのとくいの主産出」が何%増えるか**
> - 自分だけに効く効果が自身の産出を +x% する → 評価対象は総産出の1/5なので **TV = x ÷ 5**
> - チーム全員に効く効果が全員の産出を +y% する → **TV = y**

**おてつだい系の自身産出変化**（サブスキル補正は 1/(1−r) で回数が増える）

| 効果 | 短縮率 r | 自身の回数増 | TV |
|---|---|---|---|
| おてつだいスピードM | 14% | 1/0.86 − 1 = **+16.28%** | 3.26 |
| おてつだいスピードS | 7% | 1/0.93 − 1 = **+7.53%** | 1.51 |
| おてつだいボーナス | 5%（全員） | **+5.26%** を5匹 | **5.26** |
| 性格 おてつだいスピード▲ | 時間×0.9 | **+11.11%** | 2.22 |
| 性格 おてつだいスピード▼ | 時間×1.075 | **−6.98%** | −1.40 |

**ここが核心**: おてつだいボーナス（TV 5.26）は おてつだいスピードM（TV 3.26）の **約1.6倍**である。個体単位で見ると「5% < 14%」だが、5匹に効くぶんを数えると逆転する。

### 4-2. 性格

各とくいと同じスケール（きのみは ×10、食材/スキルは ×13.9、オールは ×19.0）で TV を換算した。▲は加点、▼は減点の大きさで、いずれも 0〜100 の絶対値で示す。

| 軸 | きのみ ▲ / ▼ | 食材 ▲ / ▼ | スキル ▲ / ▼ | オール ▲ / ▼ |
|---|---|---|---|---|
| おてつだいスピード | **22** / **14** | **31** / **19** | **31** / **19** | **42** / **27** |
| 食材おてつだい確率 | 0 / 0 | **56** / **56** | 4 / 4 | 19 / 19 |
| メインスキル発生確率 | 3 / 3 | 4 / 4 | **56** / **56** | 30 / 30 |
| げんき回復量 | 3 / 4 | 4 / 5 | 4 / 5 | 6 / 7 |
| EXP獲得量 | 12 / **18** | 17 / **25** | 17 / **25** | 23 / **34** |

**行ごとの根拠**

- **おてつだいスピード**: ▲は速度 ×1.11（自身 +11.1%、TV 2.22）、▼は ×0.93（自身 −6.98%、TV 1.40）。**非対称なので ▲ と ▼ を同じ重みにしてはいけない**。▼ のほうが約4割軽い。
- **食材おてつだい確率**: ×1.2 / ×0.8。食材とくいでは主産出そのものが ±20% 動く（TV 4.0）。きのみとくいでは ▼ がむしろ**きのみ産出を +3.5% する**ため、加点でも減点でもない（いじっぱり＝スピード▲/食材▼ がきのみ最良性格の一角とされる理由）。アプリ実装では 0 を推奨するが、食材も拾わせたいなら ▲ 3 / ▼ 3 程度でよい。
- **メインスキル発生確率**: ×1.2 / ×0.8。スキルとくいでは食材確率と対称に TV 4.0。他とくいでは基礎発生確率が低いため影響が小さい。
- **げんき回復量**: 3-2節のとおり、睡眠8時間なら ▼▼ の損失は約1.7%（TV 0.34）、▲▲ は上限100に張り付いてほぼ無効。**5軸のうち最も軽い**。ユーザーの睡眠時間を入力できるなら、6時間未満のとき重みを3〜4倍にする実装が望ましい。
- **EXP獲得量**: 産出には一切影響しないが、×0.82 は必要EXPが約22%増えることを意味する。Lv.70・Lv.80 でサブスキル枠が開く現仕様では、**育てきれないこと自体が最大の減点**になる。▼ を ▲ より重くしているのは、「EXP▲ で早く育つ」利得より「EXP▼ で最後まで育てられない」損失のほうが実害が大きいため。[shimo775](https://note.com/shimosaki775/n/nb9637651111b) も EXP▲ +1点 / EXP▼ −1点 と、おてつだいスピード▼（−0.5点）の倍に置いている。

### 4-3. 実装メモ

- 0〜100の整数重みをそのまま「サブスキル5枠の合計 + 性格▲ − 性格▼」で足し上げる設計なら、上表は素直に使える。ただし**おてつだい時間の35%上限**だけは加算前に判定が要る（スピードM + スピードS + おてつだいボーナスで 26%、そこに他メンバーのおてつだいボーナスが乗ると上限に当たる）。上限超過分は重み0にするのが正確である。
- 食材確率アップ・スキル確率アップは S と M が加算されるため、両積みの評価は単純な足し算で正しい（S 50 + M 100 = 150 は TV 10.8 に対応し、線形性が保たれている）。
- 最大所持数アップは、ユーザーの睡眠時間と対象ポケモンのおてつだい間隔があれば 3-4節の式で動的に計算できる。固定重みは「睡眠8.5時間・未進化〜1段進化」を前提にした中央値である。

## 5. モデルとコミュニティ評価が食い違う点

| # | 論点 | 本モデル | 一般的なコミュニティ評価 | 判断 |
|---|---|---|---|---|
| 1 | **おてつだいボーナスの順位** | 全とくいで1〜2位（きのみ53／食材73／スキル73／オール100） | 「強いが きのみの数S・食材確率アップM の次」 | **モデルを採る。** 個体単位で見ると 5% < 14% だが、5匹ぶんを数えると 5.26 > 3.26 で逆転する。依頼文の方針（チーム効果は満額）にも合う。ただし「チームに入れ続ける個体」でないと払い戻しがない点、および35%上限で3個目以降が死ぬ点は注記が必要 |
| 2 | **最大所持数アップときのみとくい** | きのみでは低評価（6）、食材・スキルで高評価（28〜31） | 「長時間放置するなら全タイプで有用」「きのみ型にも欲しい」 | **モデルを採る。** あふれ時にきのみはエナジー変換されるが食材は消え、スキル抽選も止まるという仕様が根拠。[Game8/最大所持数](https://game8.jp/pokemonsleep/565251) で確認済み |
| 3 | **げんき回復量▼▼ の重さ** | 軽い（3〜7） | 「ハズレ性格」「避けたい」と強く忌避される | **モデルを採るが、条件を明示する。** Ver.1.1.0 の 0.8→0.88 緩和で実害が激減し、睡眠スコア100なら げんき88＝最速帯の中に収まる。忌避感は旧仕様の記憶と「100にならない」見た目の不快感が大きい。短時間睡眠のユーザーには重みを上げる実装が正解 |
| 4 | **スキルレベルアップM** | スキルとくいで83（2位） | 2026年の評価は**下落**。「メインスキルのたねが余るようになり価値が落ちた」（[teketeke 2026-03-09](https://game.teketekemylife.com/entry/20260309/1773024159)） | **コミュニティを一部採る。** 効果量としては83が正しいが、たねで代替できる＝「このサブスキルでしか得られない価値」ではない。アプリに「たねの余剰」設定を置けるなら、余剰ありで 50、なしで 83 と切り替えるのが正確。単一値にするなら **65** 前後が妥当 |
| 5 | **EXP獲得量の重さ** | 重い（▼で18〜34） | カジュアルなランキングでは「誤差」扱いされがち | **モデルを採る。** Ver.3.6.0 で Lv.70/80 にサブスキル枠が移った以上、レベルを上げきれるかどうかが個体価値を決める。厳選勢（shimo775 など）の評価とは一致している |
| 6 | **きのみの数S の絶対的地位** | きのみとくいで100（2位の倍近い） | 「必須級」だが「Lv60解放以降やや崩れてきた」（teketeke 2026） | **概ね一致。** 「崩れてきた」のは、解放レベルが下がって他の金スキルにも手が届くようになったため。1位であることは変わらない |
| 7 | **食材とくいへの きのみの数S** | ほぼ無価値（4） | 「あっても無駄ではない」 | **モデルを採る。** wikiwiki も「あまり相性はよくない」と明記。あふれを1.5倍速で招き、食材を止める |

## 6. 未解決・追加調査が必要な点

1. **メインスキル発生確率の種族別基礎値**。wikiwiki は「解析情報」として外部リンクに逃がしており、公開の確定値表が見つからなかった。スキルとくいの重みは「基礎3.5〜7%」という仮定に依存しているが、スキル確率アップが**乗算**である以上、基礎値が変わっても**相対的な重み（×1.36 = +36%）は変わらない**。したがってアプリの重み表には影響しない。
2. **1日あたりメインスキル発生回数の上限の具体値**。Ver.3.3.0 で公式が存在を認めて緩和したが、閾値は非公開。コミュニティ推定は30回前後。スキル型を複数編成するチームでは スキル確率アップの重みが逓減するが、単体評価では織り込めない。
3. **睡眠EXPボーナスの重複が加算か乗算か**。[課金中毒者の日記](https://www.fireyoshida.com/entry/2023/08/27/101411)は加算（1 + 0.14n）とし、[Game8](https://game8.jp/pokemonsleep/561283) は乗算（1.14 × 1.14）と読める記述をしている。単体評価では1匹ぶんしか見ないため結論は変わらないが、チーム編成支援機能を作るなら要検証。
4. **オールとくいの食材個数と基礎確率**。「増える」としか記載がなく、食材とくいと同等なのか中間なのかが不明。オールの重みは 0.35/0.25/0.40 という配分仮定に依存している。
5. **RaenonX のデータ取得**。JavaScript 描画のため静的取得できなかった。`SleepAPI`（GitHub）に公開データがあるはずだが、今回はファイルパスを特定できなかった。定数の機械的な裏取りをするならここが本命。
